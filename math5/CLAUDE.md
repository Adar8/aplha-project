# MATH 5 — הוראות עבודה קבועות

אפליקציית לימוד עברית (RTL) שמכינה תלמיד ספציפי לבגרות במתמטיקה 5 יחידות, קיץ 2027. ציונים קודמים: 58 (שאלון 581), 43 (582). יעד: 80 ומעלה, שאיפה ל-90. 6–8 שעות לימוד בשבוע. מתכונת הבחינה (ישנה 581/582 או חדשה 571/572) טרם הוכרעה — התוכן תומך בשתיהן, ומתחיל מהחומר המשותף.

## הכלל המחייב היחיד שחייב להיזכר בכל משימה
**כל שינוי תוכן מחייב מעבר מלא על `docs/quality-standards.md` לפני שמשימה ב-`TASKS.md` מסומנת "הושלם".** זה כולל ביקורת מתמטית עצמאית, בדיקת תוכן, בדיקת התאמה לבגרות לפי מיומנויות, סימולציית תלמיד, ובדיקות רגרסיה — ראו שם את הרשימה המלאה. אין אישור עצמי: הסוכן שכתב את התוכן אינו הסוכן שמאשר אותו.

## מסמכי מצב — קראו אותם בתחילת כל סבב עבודה
- `ROADMAP.md` — סדר בנייה לפי תרומת נקודות בגרות לשעת עבודה.
- `TASKS.md` — לוח משימות חי: עדיפות, תלות, סטטוס, סוכן אחראי, קריטריון הצלחה.
- `docs/decision-log.md` — למה הוחלט מה שהוחלט (תאריך, מה, למה, ראיה).
- `docs/exam-catalog.json`, `docs/coverage-matrix.json`, `docs/curriculum-map.json` — **נוצרים אוטומטית**, אל תערכו ידנית. עדכנו עם `npm run gen:all` (מתוך `math5/`).
- `docs/reports/` — דוחות סוכנים (ביקורת, תלמיד, נבחן, QA), בעברית.
- `docs/lessons-learned/` — מסקנות משמעותיות (לא תיקון נקודתי): מה התגלה · למה · השפעה · תיקון · מניעת הישנות · בדיקות שנוספו · שיעורים אחרים שנבדקו.
- `docs/quality-standards.md` — התקן המחייב המלא (9 סעיפים: שער איכות, הפרדת תפקידים, מדידת כיסוי ב-4 מדדים נפרדים, זכויות יוצרים, איסור המצאה, RTL, מדד איכות 100 נק', מאגר הערכה עצמאי, מחזור שיפור ובקרה אוטומטית).

## מערך הסוכנים (`.claude/agents/` בשורש המאגר)
תשעה סוכנים ייעודיים, כל אחד עם תחום אחריות, מקורות מידע מותרים, הרשאות מינימליות, ותהליך עבודה — ראו כל קובץ סוכן לפרטים:

| סוכן | תפקיד |
|---|---|
| `exam-analyst` | קורא שאלוני בגרות רשמיים, בונה blueprint של נושא/ניקוד/מיומנויות לכל שאלה (בלי להעתיק נוסח) |
| `curriculum-architect` | מתכנן סדר בנייה, עורך קבצים משותפים (`tools/integrate-lesson.mjs`) |
| `lesson-builder` | כותב שיעור אחד שלם ומקורי, לא מאשר את עצמו |
| `math-auditor` | ביקורת מתמטית עצמאית — לעולם לא על תוכן שהוא עצמו כתב |
| `student-simulator` | תלמיד חלש שלומד רק מהמסך (לא קורא קוד), מדווח חוויית משתמש |
| `independent-examiner` | מתחיל מאפס, לומד רק מהאפליקציה, ניגש לבגרות מלאה בתנאי מבחן |
| `qa-regression` | מריץ את כל סוללת הבדיקות האוטומטיות, מדווח בלי לתקן |
| `supervisor` | מתאם בין הסוכנים לפי `TASKS.md`/`ROADMAP.md`, לא כותב תוכן ולא שופט בעצמו |
| `ui-ux-designer` | עיצוב ממשק/חוויית משתמש, עומס קוגניטיבי, RTL, נוסחאות/שרטוטים, עקביות עיצובית — לא משנה תוכן מתמטי/לוגיקה, לא עורך את האפליקציה בפועל בלי אישור (נוסף 26.11.2026, Development Cycle 03) |

סוכנים ישנים מהתקופה שלפני המבנה הזה (`math5-builder`, `math5-evaluator`, `math5-student`, `math5-examinee`) עדיין קיימים ונשארים שמישים, אך הזרימה החדשה היא דרך תשעת הסוכנים שלמעלה.

## פקודות הפעלה
מתוך `math5/`:
```
npm test              # בודק תוכן + יחידה (מהיר)
npm run test:e2e      # דפדפן אמיתי (Playwright)
npm run test:all      # שניהם
npm run audit         # מדדי כיסוי/איכות גולמיים (tools/audit.mjs)
npm run gen:all       # מעדכן את שלושת קבצי ה-docs/*.json
node tools/check-lesson.mjs learning-content/lessons/<id>.json   # בדיקת שיעור בודד לפני אינטגרציה
node tools/integrate-lesson.mjs <id>                              # חיבור שיעור (curriculum-architect בלבד)
```
להפעלת סוכן: `/agents` ברשימה, או לבקש ישירות בשיחה ("תריץ את lesson-builder על...", "תריץ את supervisor").

`/math5-status` (מצב כללי) · `/math5-agents` (רשימת סוכנים) · `/math5-exams` (איסוף בגרויות) · `/math5-coverage` (רענון מדדים) · `/math5-plan` (עדכון תוכנית לימודים) · `/math5-build` (בניית שיעור הבא, עם כל שערי האיכות) · `/math5-verify` (ביקורת מתמטית ממוקדת, מהיר) · `/math5-student` (סימולציית תלמיד) · `/math5-exam` (הערכה עצמאית) · `/math5-qa` (בדיקות מערכת מלאות) · `/math5-fix` (טיפול במשימות שנכשלו) · `/math5-report` (דוח התקדמות) · `/math5-cycle` (מחזור עבודה מלא) · `/math5-resume` (המשך מהנקודה שנעצרה) · `/math5-audit` (ביקורת מלאה ומקיפה — שבועית, לא על כל שינוי קטן).

## מי משגר בפועל (עודכן Development Cycle 03, 26.11.2026)
**סוכן-משנה לא יכול לשגר סוכן-משנה נוסף דרך כלי `Agent`** (מגבלת סביבה, התגלתה אמפירית ב-26.11.2026 — ראו `docs/decision-log.md`). לכן החלוקה הקבועה היא:
- **הסשן הראשי של Claude Code הוא מפעיל הסוכנים בפועל.** כל דיספאץ' אמיתי (`exam-analyst`, `lesson-builder`, `math-auditor`, `student-simulator`, `independent-examiner`, `qa-regression`, `curriculum-architect`) יוצא מהסשן הראשי, לא מ-`supervisor` כסוכן-משנה.
- **`supervisor` אחראי על תכנון, סדר משימות, איסוף תוצאות ובקרת איכות** — קורא `TASKS.md`/`ROADMAP.md`/`coverage-matrix.json`, ממליץ על סדר עדיפויות, מרכז תוצאות דוחות, ומוודא ששערי האיכות (`docs/quality-standards.md`) לא נעקפים. הוא לא משגר בעצמו.
- זה לא "תוקן בתיעוד בלבד": הוכח במחזור הזה דרך מחזור עבודה אמיתי (בנייה → ביקורת עצמאית → תיקון → בדיקה חוזרת) שהסשן הראשי ביצע בעצמו על `geometric-sequence` — ראו `docs/decision-log.md` 26.11.2026 (Development Cycle 03).

## כללים כלליים
- אסור להעתיק שאלת בגרות רשמית בלי תיוג `source.label: "official"`, קישור מדויק והודעת זכויות יוצרים (ראו `docs/quality-standards.md` §4).
- אסור לדווח שבדיקה עברה בלי להריץ אותה בפועל בסבב הנוכחי (ראו §5 שם).
- ענף העבודה הנוכחי אינו `main` — לא ממזגים אוטומטית.
- עברית, RTL, נוסחאות תמיד בתוך `$…$` (ראו §6 שם — תקלות אמיתיות שכבר קרו).
- כיסוי בגרות נמדד בארבעה מדדים נפרדים — אסור לאחד אותם לציון אחד (§3).
- `learning-content/exams/eval-reserved/` אסור לגמרי ל-`lesson-builder`/`student-simulator` (§8).
- מסקנה משמעותית מבדיקה → שורה ב-`docs/lessons-learned/`, כולל בדיקה בפועל של שיעורים דומים, לא רק "צריך לבדוק" (§9).
